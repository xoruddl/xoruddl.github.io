## 개요

TypeScript는 실행 전에 타입을 검사하지만, 실행 중 서버나 사용자에게서 들어오는 값의 모양을 자동으로 확인하지는 않는다. **런타임 데이터 검증**은 실제로 들어온 값이 기대한 조건에 맞는지 프로그램이 실행되는 동안 확인하는 것이다.

## 타입 단언만으로는 부족하다

다음 코드는 응답을 `User`라고 가정하지만 실제 데이터를 검사하지 않는다.

```ts
interface User {
    name: string;
    age: number;
}

async function loadUser(): Promise<User> {
    const response = await fetch("/api/user");
    return (await response.json()) as User;
}
```

서버가 `age`에 문자열을 보내더라도 단언은 이를 발견하지 못한다. 이후 숫자 메서드를 호출하면 실행 중 오류가 날 수 있다.

## unknown으로 받고 검사하기

외부 데이터는 `unknown`으로 받은 뒤 실제 속성을 확인하자.

```ts
interface User {
    name: string;
    age: number;
}

function isUser(value: unknown): value is User {
    return typeof value === "object" && value !== null
        && "name" in value && typeof value.name === "string"
        && "age" in value && typeof value.age === "number"
        && Number.isFinite(value.age) && value.age >= 0;
}

async function loadUser(): Promise<User> {
    const response = await fetch("/api/user");
    if (!response.ok) throw new Error("사용자 요청 실패");

    const data: unknown = await response.json();
    if (!isUser(data)) throw new Error("잘못된 사용자 데이터");
    return data;
}
```

이 검사는 `name`이 문자열인지, `age`가 유한한 0 이상의 숫자인지 확인한다. `isUser`가 참을 반환하면 TypeScript도 `data`를 `User`로 다룬다. 실제 서비스에서는 이름 길이, 나이의 정수 여부 등 필요한 규칙을 추가해야 한다.

## 검증이 필요한 경계

API 응답 외에도 폼 입력, `localStorage`, 파일 내용처럼 프로그램 바깥에서 온 값은 확인이 필요하다. 데이터 구조가 커지면 스키마 검증 라이브러리를 사용해 규칙과 오류 메시지를 관리할 수도 있다.

클라이언트에서 검사하더라도 서버는 요청을 별도로 검증해야 한다. 네트워크 오류, HTTP 오류, JSON 파싱 실패와 검증 실패도 호출하는 쪽에서 처리한다.

## 정리

타입 검사는 개발 중 코드의 일관성을 확인하고, 런타임 검증은 실제 입력이 기대한 조건을 만족하는지 확인한다. 외부 값은 `unknown`으로 받아 검사한 뒤 안전하게 사용하자.
