## 개요

이미 정의한 타입을 활용하면 같은 정보를 여러 번 적지 않고 새로운 타입을 만들 수 있다. 7편에서 배운 `keyof`에 이어 인덱스 접근 타입과 매핑된 타입을 살펴본다.

## 인덱스 접근 타입

객체 타입의 특정 속성에 대괄호로 접근하면 그 속성의 타입을 꺼낼 수 있다.

```ts
interface User {
    id: number;
    name: string;
    active: boolean;
}

type UserName = User["name"]; // string
type UserValue = User["id" | "name"]; // number | string
type AnyUserValue = User[keyof User]; // number | string | boolean
```

원본 `User`의 속성 타입이 바뀌면 이를 참조하는 타입도 함께 바뀐다.

## 배열 요소의 타입 꺼내기

배열 타입에 `number`로 접근하면 요소의 타입을 얻는다.

```ts
// users 타입: { id: number; name: string }[]
const users = [{ id: 1, name: "민지" }, { id: 2, name: "지민" }];
type User = (typeof users)[number];
// { id: number; name: string }
```

타입 위치의 `typeof users`는 변수 `users`의 타입을 가져오고, `[number]`는 그 배열의 요소 타입을 가져온다.

## 매핑된 타입

매핑된 타입은 키들의 집합을 순회하며 속성을 만드는 방법이다. 모든 속성을 선택 속성으로 바꿔 보자.

```ts
type MyPartial<T> = {
    [K in keyof T]?: T[K];
};

interface User {
    id: number;
    name: string;
}

const update: MyPartial<User> = { name: "민지" };
```

`keyof T`는 원본의 키를 모으고, `K in`은 각 키를 순회한다. `T[K]`는 해당 키의 값 타입이며 `?`는 속성을 선택 사항으로 만든다. 결과적으로 내장 `Partial<User>`와 같은 형태가 된다.

## Pick의 원리

이번에는 선택한 키만 남기는 타입을 만들어 보자.

```ts
type MyPick<T, K extends keyof T> = {
    [P in K]: T[P];
};

type UserName = MyPick<User, "name">; // { name: string }
```

`K extends keyof T`는 고른 키가 원본에 실제 존재하도록 제한한다. 이렇게 기존 타입을 바탕으로 새 타입을 만들면 속성 정의를 중복하지 않아도 된다.

## 정리

인덱스 접근 타입은 기존 타입에서 속성의 타입을 꺼낸다. 매핑된 타입은 키를 순회해 새 객체 타입을 만들며, `Partial`과 `Pick` 같은 유틸리티 타입의 바탕이 된다.
